Caso de estudio principal

Sistema de Gestión de Ventas

Sistema de gestión de ventas para la PYME Comercio Ya, para el registro de su información, adaptada para el perfecto analisis de datos de la compañía. El objetivo fue migrar su datos recopilados a una base de datos relacional en SQLite que permitiera almacenar, consultar y manipular información de clientes, productos y transacciones de manera confiable y eficiente para el desarrollo de la empresa

📋 Descripción

El proyecto consistió en desarrollar un sistema básico de gestión de ventas para la PYME 'Comercio Ya', que llevaba su información en planillas con errores frecuentes. Se diseñó e implementó una base de datos relacional en SQLite con tres tablas principales (Clientes, Productos, Ventas), se crean los datos de prueba y se ejecuta de forma progresiva variadas consultas para demostrar su funcionalidad como capacidad.

⚡ Desafío principal

El principal desafío fue diseñar correctamente la estructura relacional de la base de datos desde cero: definir qué tablas crear, qué campos incluir en cada una, cómo establecer las claves primarias y foráneas para mantener la integridad referencial, y cómo asegurarse de que las relaciones permitieran responder las preguntas de negocio reales de la empresa. Un error en el diseño inicial impactaría en todas las consultas posteriores. A esto se sumó el desafío de formular subconsultas anidadas para resolver preguntas complejas como identificar el cliente que más gastó o el producto más vendido.

💡 Solución propuesta

Se desarrolló la solución en 6 etapas progresivas , comenzando por el aspecto más importante del diseño conceptual de la base de datos y avanzando hacia consultas de mayor complejidad. Se crean las tablas con sus relaciones, se insertaron registros de prueba representativos y se ejecutaron consultas de cada tipo requerido. Para las subconsultas más complejas se descompuso el problema en partes: primero entender qué dato se necesitaba, luego construir la consulta interna y finalmente anidarla en la consulta externa.

🛠️ Herramientas utilizadas

SQLite Online como entorno principal de implementación y pruebas · Lenguaje SQL con comandos DDL (CREATE, ALTER, DROP) y DML (INSERT, UPDATE, DELETE, SELECT) · Funciones de agregación: SUM(), AVG(), COUNT(), MAX() · Cláusulas: JOIN, GROUP BY, ORDER BY, HAVING, subconsultas anidadas.

📚 Aprendizajes alcanzados

Comprendí la importancia del diseño relacional previo: un modelo bien pensado facilita enormemente las consultas posteriores. Aprendí a diferenciar cuándo usar funciones de agregación versus subconsultas. El cómo combinar múltiples tablas con JOIN para responder preguntas de negocio reales y la importancia de documentar cada modificación para mantener una cohesión en el grupo de trabajo para el sistema.

💻 Habilidades técnicas aplicadas

Diseño de bases de datos relacionales Normalización de datos DDL: CREATE, ALTER, DROP DML: INSERT, UPDATE, DELETE, SELECT Consultas con JOIN (INNER JOIN) Funciones de agregación: SUM, AVG, COUNT, MAX Cláusulas GROUP BY, ORDER BY, HAVING Subconsultas anidadas Pensamiento lógico orientado a problemas de negocio

✅ Justificación ¿Por qué elegí este proyecto?

Elegí este proyecto porque representa el núcleo del trabajo de un Analista de Datos:, que en la mayoria de los casos actuales se trata de manejar datos estructurados, por lo cual el entender cómo se relacionan y extraer información útil para la toma de decisiones es el paso escencial para un profesional en análisis de datos. Para ello el diseño la base de datos, poblarla y construir consultas que respondieran preguntas de negocio concretas permite entender a profundidad este aspecto fundamental del ordenamiento de datos de las empresas.
